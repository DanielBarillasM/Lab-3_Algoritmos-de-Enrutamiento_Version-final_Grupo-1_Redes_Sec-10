\section{Metodologia de evidencia}

Las salidas de este documento fueron leidas directamente de los dispositivos de la topologia guardada. No son resultados esperados escritos antes de la prueba. Primero se verificaron enlaces e IP, luego adyacencias, tablas de enrutamiento, ECMP, DUAL, pings y trazas.

\begin{evidencia}
Estado de salud del proyecto: cero enlaces caidos y cero direcciones IP duplicadas. Ocho pings representativos, incluida la nueva VLAN 30, terminaron con cuatro respuestas de cuatro intentos.
\end{evidencia}

\end{evidencia}

\begin{evidencia}[title={Comando solicitado: show ip ospf interface Serial0/0/0}]
\begin{verbatim}
Serial0/0/0 is up, line protocol is up
  Internet address is 10.0.0.1/30, Area 0
  Process ID 1, Router ID 1.1.1.1
  Network Type POINT-TO-POINT, Cost: 20
  Neighbor Count is 1, Adjacent neighbor count is 1
    Adjacent with neighbor 2.2.2.2
\end{verbatim}
\end{evidencia}

Los dos siguientes saltos tienen metrica 21. El primero usa el enlace directo y el segundo pasa por R-CENTRAL. La salida de \texttt{show ip ospf interface} confirma area, estado, vecino y costo del enlace; \texttt{show ip route} demuestra los dos caminos instalados porque es el comando que lista los siguientes saltos.

\section{Evidencia EIGRP 75/25 y condicion de factibilidad}

\begin{evidencia}[title={Comando: show ip eigrp topology 172.16.0.0 255.255.255.128}]
\begin{verbatim}
IP-EIGRP (AS 100): Topology entry for 172.16.0.0/25
  State is Passive, 2 Successor(s), FD is 2170112
  Routing Descriptor Blocks:
  10.0.0.14 (Serial0/0/0)
      Composite metric is (2170112/2816), Route is Internal
      Total delay is 20010 microseconds
  10.0.0.18 (Serial0/0/1)
      Composite metric is (6510336/1683712), Route is Internal
      Total delay is 189550 microseconds
\end{verbatim}
\end{evidencia}

Antes de aplicar \texttt{variance}, el camino directo es el sucesor y el camino por el central es sucesor factible porque $1\,683\,712<2\,170\,112$. Con \texttt{variance 3} ambos se instalan; la relacion de metricas es exactamente $3:1$, de donde se obtiene el reparto aproximado 75/25.

\section{Redistribucion y resumen}

\begin{evidencia}[title={Ruta resumida vista desde ambos routers EIGRP}]
\begin{verbatim}
R-EIGRP-1# show ip route 192.168.0.0 255.255.254.0
Known via "eigrp 100", distance 90, metric 6996480
* 10.0.0.18, via Serial0/0/1

R-EIGRP-2# show ip route 192.168.0.0 255.255.254.0
Known via "eigrp 100", distance 90, metric 6996480
* 10.0.0.22, via Serial0/0/1
\end{verbatim}
\end{evidencia}

Las redes del otro dominio aparecen como OSPF E1, lo que demuestra la redistribucion desde EIGRP hacia OSPF. En sentido opuesto, la metrica semilla EIGRP configurada fue \texttt{1544 20000 255 1 1500}. La ruta OSPF se anuncia al lado EIGRP como el resumen \texttt{192.168.0.0/23}.

\begin{evidencia}[title={Resumen EIGRP publicado como una sola externa OSPF E1}]
\begin{verbatim}
R-CENTRAL# show ip route static
S 172.16.0.0/24 is directly connected, Null0

R-OSPF-1# show ip route ospf
O E1 172.16.0.0/24 [110/30] via 10.0.0.6, Serial0/0/1
\end{verbatim}
\end{evidencia}

El IOS emulado no admite \texttt{summary-address} para las externas OSPF. La solucion compatible crea \texttt{172.16.0.0/24} hacia Null0 en R-CENTRAL y redistribuye esa unica estatica con \texttt{redistribute static metric-type 1 subnets}. Las rutas EIGRP especificas permanecen en el central y ganan por coincidencia de prefijo mas largo, por lo que Null0 no afecta la conectividad. El lado OSPF recibe exactamente una ruta E1 para todo el dominio EIGRP.

\section{Conclusion de verificacion}

La topologia satisface conectividad extremo a extremo entre las siete LAN/VLAN. OSPF mantiene dos caminos de costo igual; EIGRP cumple la condicion de factibilidad e instala dos rutas con relacion de metrica 3:1. R-CENTRAL conserva el alcance entre protocolos y publica un solo resumen por dominio: \texttt{192.168.0.0/23} hacia EIGRP y \texttt{172.16.0.0/24} como OSPF E1.
