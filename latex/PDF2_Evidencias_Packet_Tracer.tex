\section{Alcance}

Este documento reúne las salidas solicitadas de Packet Tracer: las tablas de enrutamiento de los cinco routers, la evidencia de balanceo OSPF y EIGRP, la redistribución con rutas resumidas y las capturas de conectividad extremo a extremo.

\section{Topología implementada}
\begin{figure}[H]
\centering
\includegraphics[width=\textwidth,trim=70 160 500 10,clip]{figuras/topologia_lab3.png}
\caption{Topología real: cinco routers, seis enlaces seriales, cuatro switches y siete equipos finales.}
\end{figure}

Los enlaces seriales forman dos triángulos que comparten R-CENTRAL. R-OSPF-1 y R-EIGRP-1 usan router-on-a-stick; R-OSPF-2 y R-EIGRP-2 usan una LAN sin VLAN adicional. R-CENTRAL no posee LAN propia y es el único router que ejecuta ambos protocolos.

\begin{decision}[Resolución de la tercera VLAN de R-EIGRP-1]
El rol general exige tres VLANs, aunque la tabla detallada enumera solo dos. Se implementó VLAN 30 de administración/servidores en \texttt{172.16.0.224/28}, con gateway \texttt{172.16.0.225} y host de prueba \texttt{172.16.0.226}.
\end{decision}

\section{Configuración base}

R-OSPF-1 enruta las VLAN 10 y 30; R-EIGRP-1 enruta las VLAN 10, 20 y 30. En ambos protocolos se utilizó \texttt{passive-interface default} y se habilitaron únicamente los enlaces seriales que forman vecindades. De esta manera las LAN/VLAN se anuncian sin enviar mensajes de descubrimiento hacia los equipos finales.

\section{Lectura de las tablas de enrutamiento}

Los códigos usados son: \texttt{C} conectada, \texttt{L} local /32, \texttt{O} OSPF interna, \texttt{O E1} OSPF externa tipo 1, \texttt{D} EIGRP interna y \texttt{S} estática. Las líneas siguientes transcriben las rutas materiales mostradas por \texttt{show ip route}; se omiten únicamente encabezados repetitivos y rutas locales /32 que no cambian la decisión de reenvío.

\section{Evidencia OSPF de costo igual}

El enunciado pide \texttt{show ip ospf interface}. Ese comando demuestra área, vecino y costo de una interfaz, pero no lista los dos next hops. Por eso se incluye el comando solicitado y se complementa con \texttt{show ip route 192.168.0.0}, que sí demuestra ECMP.

\begin{evidencia}[Comando solicitado: show ip ospf interface Serial0/0/0]
\begin{verbatim}
R-OSPF-1# show ip ospf interface Serial0/0/0
Serial0/0/0 is up, line protocol is up
  Internet address is 10.0.0.1/30, Area 0
  Process ID 1, Router ID 1.1.1.1
  Network Type POINT-TO-POINT, Cost: 20
  Neighbor Count is 1, Adjacent neighbor count is 1
    Adjacent with neighbor 2.2.2.2
\end{verbatim}
\end{evidencia}

\begin{calculo}[Cálculo de los dos caminos]
\[
C_{directo}=20+1=21,
\qquad
C_{\text{vía central}}=10+10+1=21.
\]
\end{calculo}

\begin{evidencia}[Prueba de ECMP: show ip route 192.168.0.0]
\begin{verbatim}
Routing entry for 192.168.0.0/24
Known via "ospf 1", distance 110, metric 21, type intra area
  Routing Descriptor Blocks:
  * 10.0.0.2, from 2.2.2.2, via Serial0/0/0
      Route metric is 21, traffic share count is 1
    10.0.0.6, from 2.2.2.2, via Serial0/0/1
      Route metric is 21, traffic share count is 1
\end{verbatim}
\end{evidencia}

Los dos bloques tienen métrica 21 y \texttt{traffic share count 1}; por tanto, OSPF instala reparto 1:1.

  10.0.0.18 (Serial0/0/1)

      Total delay is 189550 microseconds
\end{verbatim}
\end{evidencia}

\begin{center}
\begin{tabular}{l r r l}
\toprule
Camino & Métrica/FD & RD & Papel\\
\midrule
Directo por 10.0.0.14 & 2,170,112 & 2,816 & Sucesor\\
Vía central por 10.0.0.18 & 6,510,336 & 1,683,712 & Sucesor factible\\
\bottomrule
\end{tabular}
\end{center}

La factibilidad se cumple porque
\[
1\,683\,712<2\,170\,112.
\]
La relación de métricas es
\[
\frac{6\,510\,336}{2\,170\,112}=3.
\]
Con \texttt{variance 3}, \texttt{maximum-paths 2} y \texttt{traffic-share balanced}, la proporción inversa es aproximadamente 75\% por el camino principal y 25\% por el alterno.

\section{Redistribución y sumarización}

\subsection{OSPF hacia EIGRP}
EIGRP exige una métrica semilla para rutas externas:
\begin{verbatim}
router eigrp 100
 redistribute ospf 1 metric 1544 20000 255 1 1500
 maximum-paths 2
 variance 3
 traffic-share balanced
\end{verbatim}
Los cinco valores son ancho de banda, retardo en decenas de microsegundo, confiabilidad, carga y MTU. El resumen se publica en las dos interfaces EIGRP de R-CENTRAL:
\begin{verbatim}
interface Serial0/1/0
 ip summary-address eigrp 100 192.168.0.0 255.255.254.0
interface Serial0/1/1
 ip summary-address eigrp 100 192.168.0.0 255.255.254.0
\end{verbatim}

\begin{evidencia}[Una sola ruta OSPF resumida en cada router EIGRP]
\begin{verbatim}
R-EIGRP-1# show ip route 192.168.0.0 255.255.254.0
Known via "eigrp 100", distance 90, metric 6996480
* 10.0.0.18, via Serial0/0/1

R-EIGRP-2# show ip route 192.168.0.0 255.255.254.0
Known via "eigrp 100", distance 90, metric 6996480
* 10.0.0.22, via Serial0/0/1
\end{verbatim}
\end{evidencia}

\subsection{EIGRP hacia OSPF}
El IOS 1941 emulado no admite el mecanismo probado para resumir externas OSPF. La solución compatible conserva las rutas EIGRP específicas en R-CENTRAL, crea el agregado /24 y redistribuye únicamente esa estática como E1:
\begin{verbatim}
ip route 172.16.0.0 255.255.255.0 Null0
router ospf 1
 redistribute static metric-type 1 subnets
\end{verbatim}

\begin{evidencia}[Una sola externa OSPF E1 para todo el dominio EIGRP]
\begin{verbatim}
R-CENTRAL# show ip route static
S 172.16.0.0/24 is directly connected, Null0

R-OSPF-1# show ip route ospf
O E1 172.16.0.0/24 [110/30] via 10.0.0.6, Serial0/0/1
\end{verbatim}
\end{evidencia}

Las rutas /25, /26, /27 y /28 ganan sobre /24 por coincidencia de prefijo más largo, de modo que Null0 no descarta tráfico válido. E1 suma el costo externo y el costo interno hasta R-CENTRAL.

\section{Conclusiones}

La topología permite comunicación entre ambos dominios. OSPF conserva dos caminos de costo igual; EIGRP instala el sucesor y el sucesor factible con \texttt{variance 3}; y R-CENTRAL intercambia una ruta resumida por cada dominio.
